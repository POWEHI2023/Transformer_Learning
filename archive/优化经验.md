# Transformer 结构的网络优化训练效率

1. 尽可能融合计算流程, 例如 FusedAttention, FlashAttention, 多个shape相似的权重可以融合, 例如 MoE 中的 Group GEMM, 减少 Kernel Launch, 大批量数据一次加载集中计算。
2. 并行 IO 与计算, Stream Overlap 数据加载与计算的流程, 避免等待, DataLoader 可以使用 Pinned Memory 实现 ZeroCopy 的效果, 避免一次额外的内存拷贝, NonBlocking 可以异步从 CPU 加载数据到 Device, 避免串行等待。
3. 尽量避免大量 To Device, 批次的数据集中 To Device, 便于异步加载和 Stream Overlap。

4. FSDP2/ Zero1/2/3/ 和 TP/ SP 并行机制, FSDP2 相比于 TP 内存占用更高一些, FSDP2 在每次 Forward/Backward 之前需要 PreForward 加载每一层的数据, TP 不需要提前加载数据, 只需要几次集合通信汇总结果。
5. TP 中分片局部 Tensor 为 DTensor, Backward 时 Optimizer 更新每个 Tensor 的权重 Parameter, 但是 ForEach/ Fuse 操作无法同时操作 Tensor 和 DTensor, 需要手动构造融合的 Parameter 便于 ForEach 减少逐项计算的调度开销。

6. Zero 优化小参数量的层, SP 并行 Sequence 比较小的 Input 时效果不明显, 并且额外引入的通信开销可能掩盖并行带来的计算性能优化, SP 可以将 Sequence 拆分, 减少层间激活值, 减少显存占用。
7. DataLoader 对于大数据量的加载, 压缩可以增加 IO To Device 的性能, 工程复杂度较高, 需要实现解码 Kernel 并且并发 IO/ Decode, 相比于 IO/ Forward Stream 增加了 Decode Stream。

# 多约束条件下的复杂系统优化问题 ?

1. Async RL & Staleness, 提高 Rollout/ Training Overlap 的同时带来 Policy Staleness, 平衡 Throughput, Freshness 和资源配比。
2. PD Disaggregation & KV Transfer Communication Cost
3. 不同 Quantization 条件下的 TP compute/ communication balance
4. Prefix Cache 中的 Scheduling 问题。
5. Graph 的 Static 和 Serving 中的 Dynamic, Shape Bucketing & Padding。
